# エッセイ・思索型 ★この文体の標準型

`note/STYLE.md` の文体で書くときの骨格。以降、指定がなければこの型を使う。

向いているテーマ: 言葉の違いが気になる / 違和感がある / うまく言えないことがある

---

## 書ける／書けないの見分け

書けるテーマ:
- 自分が実際に「あれ？」と思った場面がある
- 結論がまだ出ていない
- 一語のキーワードに絞れる（「座る」「親しみ」「待つ」）

書けないテーマ:
- 結論が先に決まっている（→ ハウツー型へ）
- 場面が思い出せない（→ まだ書くタイミングではない）

## 骨格

```markdown
（最近◯◯について考えている ＋ 誤解の先回り否定 (笑)）
（同じ形なのに逆のことが起きる、という提示）
（「これは何なんだろう」）

## 「（具体的な場面を一言で）」
★ 自分が実際に見た場面。150〜300字。ここが抽象だと全部ふわっとする

## 「（よくある説明）で、片づけたくない。」
世間の説明を出して、それでは足りないと言う

## 「（自分の言い換え1）」
## 「（自分の言い換え2）」
中心概念を、否定を積んで定義し直す

## 「（反対側の事例）も、たぶん同じ穴。」
反対に見えるものが、実は同じことをしている、という転回

## 「（結論にあたる一言）」
★ 自分の体験をもう一つ入れられるとよい

## 「（予想される反論への応答）」
「◯◯すればいい」に距離を置く。脱がなくていい、崩さなくていい、の形

## 「（仕事・組織への接続）」
身近な場面に降ろす。職場、家族、面談、飲み会

## 「自分も、やっている。」
★ 自分の弱さを認めるセクション。この文体ではここが効く

## 「それでも、◯◯していい。」
否定で終わらせない。ひっくり返す

---
（短文を改行で連打して速度を上げる）
（あなたは、どう思いますか）
（読者への呼びかけで終わる）
```

## チェック

- [ ] キーワードを1語に絞り、言い換えずに繰り返したか
- [ ] 1行1文になっているか（箇条書き記号を使っていないか）
- [ ] 「て」止めが4〜6回に収まっているか
- [ ] 見出しが全部「」の断片フレーズになっているか
- [ ] 自分の具体的な場面が最低1つ入っているか
- [ ] 結論を出しきっていないか（出しきると別の文体になる）
- [ ] `(笑)` が1〜2回か
- [ ] 最後がまとめではなく問いか
